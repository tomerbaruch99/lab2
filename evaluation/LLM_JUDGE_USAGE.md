# LLM-as-a-Judge Usage Guide

## Overview

The project has two separate evaluation systems:

1. **Retrieval Evaluation** (`generate_evaluation_results.py`)
   - Evaluates retrieval performance (similarity scores, precision, recall)
   - Uses `embedding_testset.json` with relevant/irrelevant document labels
   - Does NOT use LLM judging

2. **Answer Quality Evaluation** (`llm_judge.py`)
   - Evaluates RAG answer quality using Gemini as a judge
   - Requires gold standard answers (not just relevant documents)
   - Evaluates: correctness, faithfulness, completeness, conciseness, overall
   - Uses a **different Gemini model** than RAG generation for unbiased evaluation

## Model Configuration

The system uses different Gemini models for different purposes:

- **RAG Answer Generation**: Uses `gemini-3-pro-preview` (configured in `utils/config.py` as `DEFAULT_GEMINI_MODEL`)
- **LLM-as-a-Judge**: Uses `gemini-2.5-pro` (configured in `utils/config.py` as `DEFAULT_LLM_JUDGE_MODEL`)

This separation ensures that the judge model is independent from the model being evaluated, providing more objective assessment.

## Key Differences

| Feature | `generate_evaluation_results.py` | `llm_judge.py` |
|---------|----------------------------------|----------------|
| **What it evaluates** | Retrieval (chunks) | Answer quality |
| **Testset format** | Relevant/irrelevant documents | Gold standard answers |
| **Metrics** | Precision, recall, similarity | Correctness, faithfulness, completeness, etc. |
| **Integration** | Standalone script | Standalone utility (can be integrated) |


## How to Use LLM Judge

### Option 1: Use the Integrated Script (Recommended)

`run_llm_judge_evaluation.py` integrates LLM judging with the testset:

```bash
python evaluation/run_llm_judge_evaluation.py \
    --testset_file tests/embedding_testset.json \
    --output_dir evaluation/llm_judge_results \
    --strategies baseline sentence adaptive \
    --top_k 5
```

**What it does:**
1. Loads queries from `embedding_testset.json`
2. Generates RAG answers for each query using each strategy
3. Creates gold answers by combining relevant documents from the testset
4. Uses `llm_judge.py` to evaluate each answer
5. Saves results to CSV files

**Output files:**
- `llm_judge_results.csv` - Detailed results per query-strategy
- `llm_judge_statistics.csv` - Aggregate statistics per strategy

### Option 2: Use `llm_judge.py` Directly

For custom evaluation, use the `judge_answer()` function directly:

```python
from evaluation.llm_judge import judge_answer
from gemini_integration import init_gemini, load_api_keys

# Initialize Gemini model
api_keys = load_api_keys("utils/api_keys.json")
from utils import DEFAULT_LLM_JUDGE_MODEL
gemini_model = init_gemini(api_keys, DEFAULT_LLM_JUDGE_MODEL)

# Judge an answer
scores = judge_answer(
    question="איך משלמים ארנונה?",
    gold_answer="תשובה נכונה מהמסמך...",
    rag_answer="תשובה מה-RAG...",
    gemini_model=gemini_model
)

print(scores)
# {
#     "correctness": 0.85,
#     "faithfulness": 0.90,
#     "completeness": 0.80,
#     "conciseness": 0.75,
#     "overall": 0.82
# }
```

### Option 3: Manual Integration

If you want to integrate LLM judging into your own script:

```python
from gemini_integration import GeminiRAG
from evaluation.llm_judge import judge_answer
from gemini_integration import init_gemini, load_api_keys

# Initialize systems
rag = GeminiRAG(api_keys_path="utils/api_keys.json")
api_keys = load_api_keys("utils/api_keys.json")
from utils import DEFAULT_LLM_JUDGE_MODEL
gemini_model = init_gemini(api_keys, DEFAULT_LLM_JUDGE_MODEL)

# Generate RAG answer
result = rag.answer_question(
    question="איך משלמים ארנונה?",
    top_k=5,
    strategy="adaptive"
)
rag_answer = result["answer"]

# Judge the answer
gold_answer = "תשובה נכונה מהמסמך הרשמי..."
scores = judge_answer(
    question="איך משלמים ארנונה?",
    gold_answer=gold_answer,
    rag_answer=rag_answer,
    gemini_model=gemini_model
)
```

## Testset Format

### For Retrieval Evaluation (`generate_evaluation_results.py`)

The `embedding_testset.json` format works for retrieval evaluation:

```json
{
  "queries": [
    {
      "query": "איך משלמים ארנונה?",
      "documents": [
        {"text": "...", "label": "relevant"},
        {"text": "...", "label": "irrelevant"}
      ]
    }
  ]
}
```

### For LLM Judge Evaluation

The same format works, but the script combines relevant documents to create gold answers:

- **Relevant documents** → Combined into gold answer
- **RAG answer** → Generated by the system
- **Judge** → Compares RAG answer to gold answer

## Metrics Explained

LLM judge evaluates on 5 metrics (0.0-1.0):

1. **Correctness** - Factual accuracy of the answer
2. **Faithfulness** - Adherence to source material (no hallucination)
3. **Completeness** - Coverage of important information
4. **Conciseness** - Clarity and brevity
5. **Overall** - General quality score

## Example Workflow

### Complete Evaluation Pipeline

```bash
# 1. Run retrieval evaluation
python evaluation/generate_evaluation_results.py \
    --testset_file tests/embedding_testset.json \
    --strategies baseline sentence adaptive \
    --top_k 5

# 2. Run LLM judge evaluation
python evaluation/run_llm_judge_evaluation.py \
    --testset_file tests/embedding_testset.json \
    --strategies baseline sentence adaptive \
    --top_k 5

# 3. Analyze both sets of results
jupyter notebook evaluation/analyze_evaluation_results.ipynb
```

## Summary

- **`generate_evaluation_results.py`**: Evaluates retrieval, does NOT use LLM judging
- **`llm_judge.py`**: Utility for answer quality evaluation
- **`run_llm_judge_evaluation.py`**: New script that integrates LLM judging with the testset
- **`embedding_testset.json`**: Works for both evaluation types (retrieval and answer quality)
